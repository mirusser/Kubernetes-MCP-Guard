# Separate Generic Approval Core From Domain Adapters

InfraGate will move toward a **Generic Approval Core** that owns the approval lifecycle, plan envelope, digest checks, approval challenges, challenge outcomes, approval grants, audit spine, review snapshot canonicalization, and pre-execution gate orchestration, while **Domain Adapters** own mutation meaning, review evidence artifacts, mutation-intent canonicalization, freshness checks, domain policy checks, execution behavior, and adapter audit payloads. This keeps the project from becoming a Kubernetes-shaped approval system while still using Kubernetes as the first concrete adapter that proves the profile against a real high-risk target.
